# SWRL и SQWRL для кредитной онтологии

Подготовлены 5 SWRL-правил и 8 SQWRL-запросов к существующим сущностям `credit_ontology.owl`. Основные файлы — `credit_swrl_rules.txt` и `credit_sqwrl_queries.txt`. В них только разделители, номер, название и текст примера. Исходная онтология, ее экземпляры и установленный Protégé не изменены.

## Чем отличаются SWRL и SQWRL

| | SWRL | SQWRL |
|---|---|---|
| Назначение | Вывести факты из известных условий | Получить таблицу данных и сводных показателей |
| Слева от `->` | Условия: классы, свойства, встроенные функции | Аналогичные условия, при необходимости операторы коллекций |
| Справа от `->` | Утверждение класса или значения свойства | Операторы `sqwrl:select`, сортировки и другие операторы результата |
| Результат | Выведенные утверждения, которые движок может экспортировать в OWL | Таблица, которая сама не добавляет утверждения в OWL |
| Наш пример | Рассчитать и вывести `dtiRatio` у записи финансовых показателей | Рассчитать DTI и показать его в таблице вместе с платежами и доходом |
| Вкладка Protégé | SWRLTab | SQWRLTab |

SQWRL использует синтаксис SWRL, но служит для запросов. Его агрегаты работают по известным экземплярам и значениям. Результат подсчета не означает, что других неизвестных объектов не существует. Операторы SQWRL сами не записывают результаты в онтологию; при выполнении движок может использовать SWRL-вывод. Подробнее: [официальное описание SQWRL](https://github.com/protegeproject/swrlapi/wiki/SQWRL).

## Важная особенность установленного плагина

В папке проекта находится Protégé 5.0.0 с `swrltab-plugin-1.0.3.jar`. Он содержит вкладки SWRLTab и SQWRLTab, но при проверке арифметическое правило завершилось ошибкой `cannot convert value of type xsd:decimal to xsd:double`. Денежные данные нашей онтологии имеют корректный тип `xsd:decimal`; менять их на `double` не требуется.

Для полного набора примеров нужен совместимый более новый комплект Protégé и SWRLTab. Одной установки нового плагина в старый Protégé 5.0.0 может быть недостаточно: версии OWLAPI должны соответствовать. Плагин и приложение здесь не обновлялись. Официальные комплекты и сведения о совместимости перечислены в [релизах SWRLTab](https://github.com/protegeproject/swrltab-plugin/releases).

Чтобы выполнить примеры уже сейчас без изменения установленного Protégé, подготовлен отдельный локальный запуск через Java API: SWRLAPI 2.0.11, Drools 7.57.0.Final и OWLAPI 4.5.9. Это настоящий движок правил и запросов, а не имитация SWRL средствами Python. Библиотеки из официального Maven Central сохранены отдельно в `.swrl-deps`; Java взята из поставки Protégé.

## Запуск в Protégé

### Префиксы и текст примера

Откройте `credit_ontology.owl` через **File → Open**. Проверьте в **Active ontology → Ontology prefixes** наличие соответствия:

```text
credit:  http://www.semanticweb.org/creditworthiness#
```

Встроенные префиксы `swrlb:` и `sqwrl:` предоставляет SWRLTab. Их полные пространства имен:

```text
swrlb:  http://www.w3.org/2003/11/swrlb#
sqwrl:  http://sqwrl.stanford.edu/ontologies/built-ins/3.4/sqwrl.owl#
```

В редактор SWRL/SQWRL не вставляют строки `PREFIX`, как в SPARQL: соответствие префиксов настраивается в онтологии/плагине. Копируйте только выражение от первого атома `credit:…` до конца заключения. Номер, название и линии-разделители в редактор не вставляйте. Каждый пример добавляется отдельно. Все пользовательские классы и свойства уже объявлены в исходной онтологии.

### SWRL

1. Выберите **Window → Tabs → SWRLTab**.
2. Создайте новое правило, задайте имя, например `R1`, и вставьте текст первого правила из `credit_swrl_rules.txt`. Сохраните правило в редакторе. Повторите для `R2`…`R5`.
3. В панели движка выполните **OWL+SWRL→Drools**, затем **Run Drools**. Первая команда передает факты и правила движку, вторая выполняет вывод.
4. Если требуется перенести выведенные утверждения в открытую онтологию, выполните **Drools→OWL**. Сохранение файла на диск — отдельная операция **File → Save As**. Для учебного эксперимента удобно сохранить отдельную копию.
5. Все эти команды относятся к SWRLTab/Drools. Обычный запуск HermiT не заменяет исполнение арифметических встроенных функций SWRLAPI.

В полном исходном файле факты, которые выводят эти правила, уже записаны: новый пункт в Individuals может не появиться. Это ожидаемо, а не ошибка. Для демонстрации реального нового вывода подготовленный скрипт использует временный снимок с удаленными выводимыми значениями и восстанавливает их правилами. Исходный OWL при этом не меняется.

### SQWRL

1. Выберите **Window → Tabs → SQWRLTab**.
2. Создайте запрос с именем, например `Q1`, и вставьте текст первого запроса из `credit_sqwrl_queries.txt`.
3. Выберите его в списке и нажмите **Run**. Результат появится в таблице.
4. Аналогично добавьте `Q2`…`Q8`. Для быстрой проверки `Q2` должен вернуть `10`, а `Q4` — `99300`.

Для запросов не нужен экспорт **Drools→OWL**: результат находится в таблице. Все атомы тела обязательны; OPTIONAL из SPARQL сюда не переносится.

## Запуск подготовленного движка из терминала

Откройте терминал в папке проекта и выполните:

```powershell
python run_credit_swrl_sqwrl.py
```

Скрипт использует уже подготовленные `.swrl-deps`, `.python-deps`, Java из `Protege-5.0.0` и вспомогательный `run_credit_swrl_sqwrl.js`. В графическом приложении ничего менять не нужно. На другом компьютере для повторения потребуется скопировать эти зависимости и файлы проверки вместе с проектом.

Запуск создает:

- `credit_swrl_sqwrl_results.md` — результаты выполнения в таблицах и описание нового вывода;
- `credit_swrl_sqwrl_validation.json` — отчет с версиями, проверками и SHA-256 исходной онтологии;
- временные снимки и журналы в `tmp/swrl_validation`.

## Что делают правила

| Правило | Смысл | Результатов в демонстрационном снимке |
|---|---|---:|
| R1 | Указывает источник дохода для DTI в той же оценке | 10 связей |
| R2 | Указывает источник долговых платежей для DTI в той же оценке | 10 связей |
| R3 | Положительный остаток на счетах означает наличие сбережений | 9 значений `true` |
| R4 | Официальный доход плюс дополнительный доход дает совокупный месячный доход | 10 значений |
| R5 | Месячные долговые платежи, деленные на месячный доход, дают DTI | 10 значений |

R3 — одностороннее правило. Из нулевого остатка нельзя вывести отсутствие всех сбережений, а наличие сбережений не означает наличие иных активов. R4 следует принятому в наших примерах разбиению дохода без двойного учета. R5 использует `monthlyDebtPayments`, а не `outstandingDebt`. При нулевом доходе R5 не применяется.

DTI хранится долей с шестью знаками: `0.25` означает 25%. Для неотрицательных значений округление выполнено как `floor(x * 1000000 + 0.5) * 0.000001`. В текстах умножение платежей на `1000000.000000` выполняется до деления. Десятичные нули здесь намеренны: SWRLAPI 2.0.11 сохраняет масштаб делимого при десятичном делении. Такой порядок сохраняет необходимую точность на исходных данных и обходит обнаруженную особенность `swrlb:round`. Все 10 результатов сверены с независимым расчетом `Decimal` и сохраненными значениями DTI. Для измененных наборов данных повторяйте числовую проверку скриптом.

SWRL выводит факты, а не обновляет значения по принципу «перезаписать старое». Если у функционального свойства уже есть другое значение, правило может привести к противоречию. На текущих данных все выводимые значения согласованы с исходными. Порогов одобрения, новых классов риска и кредитного скоринга в примерах нет.

## Что показывают запросы

| Запрос | Результат | Строк |
|---|---|---:|
| Q1 | Возраст и регион всех профилей, возраст по убыванию | 10 |
| Q2 | Число профилей | 1, значение 10 |
| Q3 | Семейное положение и количество профилей | 3 |
| Q4 | Средний месячный доход | 1, значение 99300 |
| Q5 | Профили с просрочками | 5 |
| Q6 | Кредиты на ремонт или мебель, поиск по строковому шаблону | 4 |
| Q7 | Профили с дополнительным доходом | 8 |
| Q8 | DTI в долях и процентах, по убыванию | 10 |

В Q2 и Q3 `makeSet` создает множество профилей, `size` считает его размер; Q3 дополнительно использует `groupBy`. В Q4 нужен `makeBag`, а не `makeSet`: одинаковые доходы разных записей должны учитываться несколько раз. `swrlb:matches` в Q6 проверяет строковый шаблон; `.*` позволяет найти слова внутри текста. Дизъюнкция находится внутри регулярного выражения, а не является оператором OR между атомами SWRL.

## Учебные источники и исправления шаблонов

Использованы предоставленные `3_SWRLправила.pdf`, `3_1_swrl3.pdf` и `4_SQWRLtab.pdf`. Их медицинские примеры адаптированы к фактическим понятиям кредитной онтологии. В текстах примеров применены ASCII-символы `^` и `->`.

Неточности шаблонов не перенесены: у арифметических встроенных функций результат является первым аргументом (`swrlb:add(?result, ?a, ?b)`); произвольные `v`/`|` между атомами не являются допустимой дизъюнкцией обычного SWRL. Положительное правило не используется для вывода факта из отсутствия утверждения. Ни один новый класс не упоминается без объявления. SQWRL не вкладывает `count` внутрь `select`: в наших запросах подсчет выполнен через коллекцию и `size`.

SPARQL также может видеть заранее материализованные выведенные RDF-тройки. Поэтому различие SWRL/SQWRL/SPARQL не сводится к утверждению, что SPARQL «никогда не видит вывод»: это зависит от графа и режима выполнения.
